# AI Collaboration and Reflection

## AI Collaboration

I used GitHub Copilot as an AI development collaborator throughout the assessment rather than asking it to generate the complete application from the beginning. My initial instruction was to first analyse the assessment requirements, identify ambiguities and assumptions, propose a simple architecture, consider the CSV structure, identify the core functionality, and plan the testing strategy before implementation.

I then used Copilot during implementation to discuss design decisions, validate approaches, generate and review smaller pieces of code, and help develop automated tests. I remained responsible for deciding which suggestions to use, checking them against the assessment requirements, running the application, and verifying the resulting behaviour.

The project was intentionally kept simple, using Python's standard library and `unittest` rather than introducing unnecessary frameworks or dependencies. The final implementation was tested from the command line and the supplied input was used to generate the required standings output for week 10.

## Reflection

One example where the AI took the wrong direction occurred while creating a test for the command-line application. The first version of the generated test fixture used an incorrect five-column CSV structure. This did not match the actual input format used by the application, which requires six columns: `week`, `match_date`, `home_team`, `away_team`, `home_goals`, and `away_goals`.

I did not accept the generated test as-is. I compared the fixture against the application's CSV validation rules, identified the mismatch, and corrected the test data to use the proper six-column format. A further issue occurred when the multiline test fixture introduced an unintended blank line, which caused the CSV reader to reject the test data. I corrected the fixture so that the CSV rows were constructed explicitly without the blank line.

This was a useful example of why I treated Copilot as a collaborator rather than as an authority. Suggestions generated by the AI still needed to be checked against the actual requirements and the behaviour of the application. I used the test failures and the existing implementation to verify the suggestion, identify the problem, and make the final decision myself.

The final test suite completed successfully with 29 tests passing.
